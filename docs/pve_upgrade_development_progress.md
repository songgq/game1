## 1. 本轮交付结论

第1阶段的配置/成长/库存/事务基础，以及第3阶段的小岛地图、工人队列和离线生产已经实现并完成自动化验收。新经济事实由服务端负责，客户端只展示服务端数据并提交带 `requestId` 的操作命令。

为避免第2阶段英雄迁移尚未完成时改变Strategy 3.0策略包兼容版本，本轮保持客户端正式版本号 `0.7.7`；待后续阶段形成完整发布包时再统一升版。

原有战斗、弹道、Strategy 3.0 和旧回放代码没有迁移英雄ID，也没有修改策略提示词、DSL或Runtime语义。

## 2. 第1阶段：已完成

### 2.1 权威配置

已建立带 `schemaVersion`、`configVersion` 和严格启动校验的配置注册中心：

- `heroes.json`：战士、长枪手、射手、法师、工人；
- `hero_upgrade_cost.json`：Lv2~Lv15卡牌、金币和角色XP成本；
- `player_level.json`：角色Lv1~Lv30累计经验与29个技能点；
- `inventory_items.json`：木材、矿石、肉及后续制造材料；
- `island_plots.json`：720×1280岛屿世界中的独立21×35 LandGrid、15地块、解锁成本和固定内容；战斗22×40网格不属于岛屿配置；
- 配置缺字段、重复ID、坐标越界、未知材料或等级表不连续时拒绝启动相关模块。

### 2.2 玩家成长与英雄升级

- 五英雄初始解锁且均为Lv1，最高Lv15；
- 英雄升级必须同时满足同英雄卡和金币；
- 升到目标等级 `N` 后发放 `N × 10` 玩家角色XP；
- 玩家角色按累计XP升至最高Lv30，每次跨级获得1技能点，共29点；
- 英雄战斗属性按配置基值和每级BP成长使用整数公式确定性计算；
- 客户端英雄成长页展示等级、定位、当前属性、卡牌、成本和升级按钮。

### 2.3 Inventory、幂等与事件账本

- Inventory同时保存总量和预留量，所有消费只允许使用 `quantity - reserved_quantity`；
- 英雄升级和地块解锁均使用玩家级事务锁；
- 同一 `commandType + requestId` 重试返回第一次结果，不重复扣费；
- 同一requestId被改成不同请求时返回 `REQUEST_ID_REUSED`；
- 成功升级写入 `HERO_UPGRADED`，跨角色等级写入 `PLAYER_LEVEL_UP`；
- 成功解锁写入 `PLOT_UNLOCKED`；
- 冲突、材料不足等确定性失败同样保存幂等结果。

## 3. 第3阶段：小岛地图与工人生产已完成

### 3.1 岛屿数据

- 岛屿世界为720×1280；经营LandGrid独立为21×35格、单格32像素，起点为 `(24, 80)`；
- 战斗地图22×40网格与岛屿LandGrid完全分离；
- 15块地按3列×5行排列，每块7×7格；
- 1~4号地初始开放，5~15号地只能依次解锁；
- 解锁同时检查前置地块、玩家等级、库存可用量；
- 扣除材料、修改地块、生成内容和写事件在同一事务提交。

### 3.2 初始固定内容

- 1号地：主屋、储物箱、工人出生标记；
- 2号地：普通农田×2、普通树×1；
- 3号地：普通农田×1、普通矿×1；
- 每块农田占用独立1×1 LandGrid单元并按网格正向显示；
- 4号地：普通树×1、基础工作台地基；
- 5~15号地内容在解锁成功时按稳定实例ID生成；
- 树矿保存Charge和恢复槽，农田保存种植时间字段，建筑保存地基/建造/完成状态，为后续阶段保留规范化数据入口。

### 3.3 客户端岛屿页

- 使用`TileMapLayer`分离水面、经营陆地和道路层，使用独立`YSortWorld`承载建筑、资源、农田和工人；
- 按权威坐标绘制完整岛屿和15地块，未使用调试色块代替正式地图；
- 已解锁地显示建筑、农田和树矿摘要；
- 未解锁地显示云雾、锁和等级要求；
- 单指/鼠标拖动平移，双指/滚轮缩放；
- 缩放范围严格为1.0~2.5，镜头不允许显示地图外大面积空白；
- 点击地块展示等级和材料条件；
- 解锁成功后刷新服务端状态并播放云雾消散效果。
- 服务端在任务激活时返回完整冻结Plan，客户端按绝对时间本地连续播放整项任务，只在任务预计结束时同步一次权威状态；客户端不自行发奖，也不再每3秒重建地图。

### 3.4 工人、队列与Reservation

- 岛屿地图只生成`IslandWorker`，不生成战斗`HeroObjects`；
- 初始1名工人，数据结构和左侧工人栏支持最多5名工人及独立FIFO队列，进入页面默认选中1号工人；
- 所选工人的非终态队列在右侧以横向小图标展示，每项可取消；普通空地点击生成移动任务，交互对象点击生成对应生产任务；
- 非终态资源/农田目标显示淡蓝色占用框并禁止其他工人重复安排；
- 库存、资源Charge、农田和建筑任务在入队前原子Reservation，材料不足或目标不可达不入队；
- 运行时异常转`SKIPPED`、释放剩余Reservation并继续下一任务，不存在`WAITING_RESOURCE`；
- 同一树/矿连续点击只在界面合并为`quantity=N`，服务端保留N个独立任务ID和N次完整往返入箱循环。

### 3.5 生产与离线推进

- 服务端在独立21×35 `IslandLandGrid`上使用固定邻居顺序、固定Tie-break的确定性A*；
- Godot `AStarGrid2D`仅用于客户端运动表现，不参与经济结算；
- 任务入队只校验/预约/验证可达，真正激活时从工人`currentCell`读当前技能修正、重新寻路并冻结Plan；
- 采集每份都执行“前往→采1份→返回箱子→Deposit”；收获返箱，播种停在最后农田，制作停在建筑且成品直接入箱；
- 支持8种配置作物的选择、种子购买、单格/批量播种和收获；作物视觉阶段由`plantedAt/readyAt/serverNow`推导；
- 支持固定地基建造和RecipeConfig制作，木板严格为木材3→木板1；制作期间占用工人，最多3个工人使用不同交互点；
- 工人任务、资源恢复、作物成长和制作均使用服务端绝对时间FastForward；单请求最多500次状态转换并可续推。
- 每名工人最多保留20条已结束任务历史，不删除任何未完成任务，避免持久化JSON无上限增长。

## 4. 新增服务接口

读取接口：

```text
GET /home
GET /player/growth
GET /heroes
GET /inventory
GET /island
```

写接口：

```text
POST /heroes/{heroId}/upgrade
POST /island/plots/{plotId}/unlock
POST /island/workers/{workerId}/tasks
POST /island/seeds/{cropId}/buy
```

英雄升级请求必须包含 `requestId` 和 `expectedLevel`；地块解锁必须包含 `requestId`。所有接口均使用现有Bearer账号鉴权。
