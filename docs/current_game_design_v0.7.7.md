## 2. 游戏定位

《翡翠纷争》是一款竖屏自动对战策略游戏。

玩家不在战斗过程中实时操作英雄，而是在战斗前完成两件事：

1. 从现有英雄中组成一支 2—5 人小队；
2. 使用自然语言描述整支队伍的战斗策略。

服务器把玩家的自然语言策略转换为确定性的战斗规则，随后在后台完成整场战斗模拟并生成回放。客户端负责展示编队、策略编辑、策略理解结果以及播放服务器返回的战斗过程。

当前核心体验是：

```text
选择阵容
  → 编写团队策略
  → 系统解释策略
  → 玩家确认
  → 服务器自动模拟
  → 客户端播放回放
  → 查看结果与历史战斗
  → 修改阵容或策略后再次挑战
```

## 3. 当前完整玩法流程

### 3.1 进入游戏

客户端启动后进入主界面。主界面已经提供：

- 玩家名称；
- 玩家头像选择；
- 玩家等级、经验、金币、钻石展示；
- 游客账号或正式账号状态；
- 开始新游戏；
- 历史战斗；
- 设置；
- 当前客户端版本展示。

等级、经验、金币和钻石当前已经具备账号字段、存储和界面展示，但尚未接入完整的战斗奖励与成长循环。

### 3.2 战前编队

玩家进入“战前编队”页面后，可以：

- 在 5 个卡组槽位之间切换；
- 修改卡组名称；
- 保存当前卡组；
- 清空当前卡组；
- 为 1—5 号位置选择英雄；
- 重复选择同一种英雄；
- 组成 2—5 人队伍。

编队必须从 1 号位开始连续排列。例如：

- 1号、2号有英雄，3—5号为空：合法；
- 1号、2号、3号有英雄，4—5号为空：合法；
- 1号有英雄、2号为空、3号有英雄：不合法。

当前敌方阵容由服务器/战斗引擎使用默认英雄顺序生成：

```text
弓箭手 → 长枪手 → 工人 → 僧侣 → 战士
```

敌方人数与玩家实际参战人数一致。若玩家只带 2 人，则敌方使用默认顺序中的前 2 名英雄。

### 3.3 团队策略编辑

编队完成后进入“团队战斗策略”页面。玩家可以：

- 在 20 个策略模板之间切换；
- 修改策略名称；
- 分多条消息输入策略；
- 编辑或删除已经输入的消息；
- 使用键盘输入；
- 使用按住说话的语音输入；
- 保存策略；
- 将策略发送给服务器理解；
- 查看每个英雄的系统执行摘要；
- 查看无法执行或被拒绝的策略片段；
- 生成策略分享码；
- 输入分享码导入策略；
- 确认策略后开始战斗。

客户端单条策略输入框限制为 100 个字符；服务端 Strategy 3.0 最多接受 30 条消息，每条服务端上限为 500 个字符。

### 3.4 策略确认与战斗模拟

策略发送后的实际流程为：

```text
客户端提交当前阵容
  → 服务器生成不可变战斗快照
  → 本地快速解析器尝试理解常见策略
  → 必要时调用大语言模型生成 Intent IR
  → 服务器确定性编译 Runtime Plan
  → 服务器校验所有对象、条件、动作和引用
  → 服务器生成“系统实际执行描述”
  → 客户端向玩家展示理解结果
  → 玩家点击开始战斗
  → 服务器按照确认版本模拟
  → 客户端播放回放
```

大语言模型不参与战斗中的逐帧决策。战斗开始后模型调用次数为 0。

### 3.5 战斗与回放

当前客户端的正式 Strategy 3.0 流程使用服务器权威模拟：

- 服务器以固定 60 Tick/秒推进战斗；
- 每 0.1 战斗秒记录一个回放帧；
- 客户端接收完整回放后再播放；
- 客户端不重新计算伤害、治疗、目标选择或胜负；
- 历史回放读取服务器保存的同一份数据。

## 4. 当前英雄系统

### 4.1 通用战斗属性

所有英雄当前都具有以下基础数据：

- 当前生命值 `HP`；
- 最大生命值；
- 普通攻击伤害；
- 普通攻击间隔；
- 攻击距离；
- 移动速度；
- 弹道命中判定半径；
- 当前坐标；
- 朝向；
- 当前攻击或治疗目标；
- 生存/死亡状态；
- 队伍和英雄编号。

当前所有英雄等级在战斗快照中为 1，尚未接入按等级变化的战斗数值成长。

### 4.2 英雄基础数值表

| 英雄 | 最大生命 | 普攻伤害 | 攻击间隔 | 攻击距离 | 移动速度 | 弹道命中半径 | 当前特殊逻辑 |
|---|---:|---:|---:|---:|---:|---:|---|
| 弓箭手 | 80 | 18 | 1.2秒 | 160 | 60 | 18 | 发射真实箭矢弹道 |
| 长枪手 | 120 | 22 | 1.2秒 | 96 | 64 | 18 | 中距离直接伤害 |
| 工人 | 110 | 6 | 1.2秒 | 32 | 56 | 18 | 采集资源；战斗人员全灭后参战 |
| 僧侣 | 100 | 8 | 1.2秒 | 192 | 72 | 18 | 优先治疗受伤队友；无治疗目标时攻击 |
| 战士 | 160 | 28 | 1.2秒 | 32 | 68 | 18 | 高生命、高伤害近战 |

数值中的距离和速度单位均为当前 Godot 战场坐标单位。

表中的半径当前用于弓箭等弹道的单位命中判定。英雄之间尚未实现互相阻挡移动的实体碰撞，因此不能把该数值理解为英雄行走时的碰撞体积。

### 4.3 攻击前摇与动作时长

英雄发动普通攻击后，不会立即结算命中。伤害或弹道在攻击动作的指定时间点产生。

| 英雄 | 命中/发射时点 | 完整攻击动画时长 |
|---|---:|---:|
| 长枪手 | 0.125秒 | 0.375秒 |
| 工人 | 0.25秒 | 0.50秒 |
| 战士 | 0.375秒 | 0.75秒 |
| 弓箭手 | 0.375秒发射箭矢 | 0.75秒 |
| 僧侣 | 0.50秒 | 0.75秒 |

攻击开始时记录目标；到达命中时点时仍会再次检查：

- 目标是否存在；
- 目标是否存活；
- 目标是否仍是敌方；
- 目标是否仍在攻击范围内。

任意检查失败，则本次攻击不造成伤害。

### 4.4 弓箭手

弓箭手是当前唯一使用实体普通攻击弹道的英雄。

弓箭基础弹道数值：

| 属性 | 数值 |
|---|---:|
| 弹道速度 | 640 |
| 弹道半径 | 6 |
| 最大飞行距离 | 弓箭手攻击距离，即160 |
| 最大生命周期 | 600 Tick |
| 穿透 | 否 |
| 友方单位阻挡 | 否 |
| 敌方单位阻挡 | 是 |

弓箭发射时固定方向，不会追踪目标之后的位置。

弓箭按照连续线段碰撞检测推进，避免高速弹道穿过单位。弹道会命中飞行路径上第一个合法敌方单位。因此：

```text
弓箭手瞄准敌方后排
  → 敌方前排先进入箭路
  → intendedTarget 仍是后排
  → actualHitTarget 变为前排
```

当前地图没有注册正式的弹道障碍物，因此当前实战中的弹道阻挡主要来自敌方英雄身体。

### 4.5 非弓箭手的普通攻击

长枪手、战士、进入战斗状态后的工人，以及僧侣的普通攻击均使用直接伤害：

- 到达攻击命中时点；
- 目标仍有效；
- 目标仍在攻击范围内；
- 直接把英雄攻击力加入本 Tick 的待结算伤害。

这些普通攻击当前不生成飞行弹道，也不会被其他英雄身体拦截。僧侣的治疗结算同样不生成可被拦截的弹道。

### 4.6 僧侣

僧侣具有治疗和普通攻击两套行为。

治疗数值：

| 属性 | 数值 |
|---|---:|
| 单次治疗量 | 18 |
| 治疗距离 | 192 |
| 治疗前摇 | 0.50秒 |
| 治疗动作时长 | 0.75秒 |
| 行动间隔 | 1.2秒 |

默认情况下，僧侣会：

1. 查找距离最近的受伤存活队友；
2. 不把自己作为默认治疗目标；
3. 目标超出距离时向目标移动；
4. 进入距离后进行治疗；
5. 治疗前再次验证目标存活、仍受伤且仍在范围内；
6. 没有受伤队友时转为攻击敌人。

玩家给僧侣明确攻击策略时，攻击命令可以覆盖默认“优先治疗”逻辑；如果玩家同时明确要求治疗，则治疗规则仍可优先。

### 4.7 工人

工人的默认职责是采集资源。

当队伍中仍有任意存活的弓箭手、长枪手、战士或僧侣时，工人保持采集模式。当这些非工人战斗单位全部死亡后，工人永久切换为战斗模式，并使用自己的普通攻击参与战斗。

工人当前可以采集：

- 黄金；
- 石头；
- 木材；
- 肉。

工人一次只携带一种资源。采集流程为：

```text
选择资源节点
  → 移动到采集距离
  → 连续攻击资源节点
  → 资源节点耗尽
  → 携带1份资源返回自己的出生位置
  → 距离出生位置24以内完成入库
  → 再选择下一个资源节点
```

采集距离：

| 资源 | 采集距离 |
|---|---:|
| 黄金 | 48 |
| 木材 | 48 |
| 石头 | 34 |
| 肉 | 34 |

采集动作：

- 肉使用小刀动作，命中时点 0.25 秒；
- 木材使用斧头动作，命中时点 0.375 秒；
- 黄金和石头使用镐动作，命中时点 0.375 秒；
- 每次工具动作同样受 1.2 秒行动间隔限制。

## 5. 生命、伤害、治疗和死亡逻辑

### 5.1 同 Tick 结算

攻击和治疗首先进入待结算事件队列，服务器在统一阶段处理。

对于同一英雄，本 Tick 最终生命值计算为：

```text
新生命值 = clamp(旧生命值 + 本Tick总治疗 - 本Tick总伤害, 0, 最大生命值)
```

这意味着同一结算阶段可以同时存在多个伤害来源和治疗来源。

### 5.2 受击状态

英雄受到大于 0 的伤害后：

- 播放受击音效和红色闪烁；
- 显示伤害数字；
- `is_under_attack` 相关状态保持 4 秒；
- 产生可供策略运行时使用的 `damage_received` 事件。

### 5.3 治疗限制

- 治疗不会超过最大生命值；
- 目标已经满血时不产生实际生命增长；
- 有效治疗播放治疗特效和治疗数字；
- 死亡英雄不能被普通治疗恢复。

### 5.4 死亡

英雄生命值降至 0 时：

- 进入死亡状态；
- 清除攻击目标、资源目标和待执行动作；
- 隐藏血条；
- 播放死亡动画和音效；
- 进入本方死亡队列；
- 触发肉复活检查；
- 触发战斗结束检查。

死亡队列按死亡先后顺序处理。

## 6. 当前资源系统

### 6.1 资源种类和地图数量

地图为双方镜像生成资源。每一方当前拥有：

| 资源 | 每方节点数 | 全图节点数 | 当前用途 |
|---|---:|---:|---|
| 黄金 | 4 | 8 | 计数展示，未接入消费 |
| 石头 | 8 | 16 | 计数展示，未接入消费 |
| 木材 | 8 | 16 | 计数展示，未接入消费 |
| 肉 | 5 | 10 | 每1肉可复活1名死亡英雄 |

每个资源节点初始具有 4 格耐久。工人需要完成 4 次有效采集命中才能耗尽节点；节点耗尽后工人才获得 1 份对应资源。

因此当前资源产出关系是：

```text
1个资源节点
  = 4次有效采集命中
  = 节点耗尽后获得1份资源
```

### 6.2 资源归属

每个资源节点属于地图一方：

- 上半场资源归红方；
- 下半场镜像资源归蓝方；
- 工人只会采集本方所属资源。

### 6.3 资源出生

资源位置由战斗随机种子的独立生成流确定，并保证同一半场中节点之间至少约 58 单位距离。上下双方位置严格镜像。

上半场资源生成范围大致为：

```text
X：48—672
Y：205—535
```

蓝方资源使用关于地图水平中线的镜像位置。

### 6.4 肉/羊

肉以羊的形式出现在地图中。

羊的当前行为：

- 移动速度 26；
- 每 2—5 秒重新选择附近随机移动点；
- 在本方半场指定范围内游走；
- 工人开始挥刀时停止移动；
- 受到采集命中时显示受击反馈；
- 节点耗尽后消失并提供 1 肉。

### 6.5 肉复活

每当队伍获得肉，或有英雄死亡时，系统都会检查复活条件。

复活规则：

```text
本方肉数量 > 0
且
本方死亡队列不为空
  → 消耗1肉
  → 复活死亡队列中最早死亡的英雄
```

复活英雄：

- 使用原英雄类型；
- 回到该英雄原出生位置；
- 保留原策略编号；
- 重新以满生命值创建；
- 继续受原编号对应的策略控制。

如果库存中已有肉，英雄死亡后可以立即触发复活。

## 7. 当前地图方案

### 7.1 基础尺寸

| 项目 | 数值 |
|---|---:|
| 逻辑画布 | 720 × 1280 |
| 地图网格 | 22列 × 40行 |
| 单格尺寸 | 32 |
| 单位可移动X范围 | 18—702 |
| 单位可移动Y范围 | 105—1235 |

游戏采用竖屏布局：红方出生在地图上方，蓝方出生在地图下方。

### 7.2 出生位置

5人阵容使用固定横坐标：

```text
72、216、360、504、648
```

- 红方出生 Y = 128；
- 蓝方出生 Y = 1152。

2—4人阵容会按照当前人数在 720 宽度内均匀排列。

### 7.3 河流与双桥

河流占据：

```text
Y = 592—688
```

两座桥中心为：

```text
左桥 X = 328
右桥 X = 392
```

两座桥并排组成中央双桥通道。水面是单位移动的硬障碍，英雄跨越双方半场时必须经过桥。

寻路会比较单位当前位置和目标位置到左右桥的总横向成本，选择代价较小的桥。一旦进入跨河流程，会锁定当前桥，直到离开河岸，防止在两座桥之间反复切换。

### 7.4 当前可用位置区域

当前正式战斗快照支持：

- `spawn_zone`：出生位置；
- `open_ground`：普通地面；
- `ally_side`：蓝方本方半场；
- `enemy_side`：蓝方敌方半场；
- `left_bridge`：左桥；
- `right_bridge`：右桥。

这些区域用于位置判断和策略移动，不是可占领、可得分的据点。

### 7.5 装饰物

地图上存在蘑菇和灌木视觉装饰，但它们当前：

- 不阻挡移动；
- 不阻挡视野；
- 不提供隐藏；
- 不属于功能性草丛；
- 不参与当前正式策略区域选择。

## 8. 默认自动战斗逻辑

如果没有玩家策略，英雄执行默认 AI。

### 8.1 普通战斗英雄

弓箭手、长枪手和战士默认：

1. 从所有存活、可见的敌人中选择距离最近者；
2. 目标在攻击范围外时向目标移动；
3. 进入攻击范围后锁定目标并攻击；
4. 目标死亡或离开有效状态后重新选择；
5. 跨河时自动选择左右桥。

### 8.2 僧侣默认逻辑

僧侣默认优先治疗距离最近的受伤队友；没有受伤队友时按普通战斗逻辑攻击最近敌人。

### 8.3 工人默认逻辑

工人在仍有其他战斗英雄存活时采集本方最近资源。所有非工人战斗英雄死亡后，工人切换为战斗状态。

## 9. Strategy 3.0 当前策略系统

### 9.1 三层策略数据

当前策略链路分为三层：

1. 玩家原始自然语言；
2. Intent IR（大模型或本地解析器理解出的战术意图）；
3. Runtime Plan（服务器生成的确定性执行规则）。

玩家和大语言模型不直接修改战斗引擎代码，也不能提交任意表达式执行。

### 9.2 当前策略生成次数

- 常见、明确语句可以由本地快速解析器处理，模型调用 0 次；
- 本地解析不完整时，正常调用大语言模型 1 次；
- 只有模型返回的内容不是合法 JSON 时，允许额外修复调用 1 次；
- 战斗模拟和回放阶段调用大语言模型 0 次。

### 9.3 当前正式可表达的主要战术

当前已完成并可编译到运行时的主要能力包括：

- 指定 1—5 号英雄执行规则；
- 按英雄类型选择执行者；
- 开局等待或保持位置；
- 保持位置但允许攻击进入射程的敌人；
- 在指定战斗时间后执行动作；
- 跟随指定编号队友；
- 移动到队友身后；
- 攻击最近敌人；
- 优先攻击指定英雄类型；
- 优先攻击正在攻击某个队友的敌人；
- 敌人靠近时后退并保持攻击距离；
- 低血量时撤回本方半场；
- 工人优先采集指定资源；
- 攻击完成后短暂后退；
- 为指定队友计算挡线位置；
- 持续调整挡线位置；
- 根据攻击前摇、箭速和移动方向预测挡线点；
- 条件不成立时跳过规则；
- 目标不存在时执行保持位置等兜底；
- 一个意图失败时保留其他独立合法意图。

### 9.4 当前可读取的核心条件

当前运行时已经具备的主要条件数据包括：

- 战斗时间；
- 战斗 Tick；
- 自身生命值、最大生命值和生命百分比；
- 自身是否存活；
- 自身攻击距离；
- 自身到威胁目标的距离；
- 自身是否正在受到攻击；
- 当前区域类型；
- 目标是否存活；
- 目标是否可见；
- 目标到自身的距离；
- 单位编号、英雄类型、生命百分比和距离；
- 目标失效、受伤、攻击完成、单位死亡和路径失败等事件；
- 有限的策略记忆和阶段状态。

### 9.5 规则优先级和动作冲突

当前运行时不会简单地把所有成立规则同时执行，而是经过：

```text
条件判断
  → 规则优先级仲裁
  → 动作资源仲裁
  → 动作提交
```

优先级从高到低包括：

1. 系统强制状态；
2. 紧急生存；
3. 保护队友；
4. 关键技能（运行时优先级预留，当前正式英雄尚未开放通用主动技能）；
5. 战斗站位；
6. 普通战斗；
7. 战术移动；
8. 跟随；
9. 空闲。

移动、朝向和主要战斗动作分别占用执行资源，避免同一个英雄在同一 Tick 同时接受两个相反移动命令。

### 9.6 动作持续和防抖

规则支持：

- 最短持续 Tick；
- 重新判断间隔；
- 进入条件与退出条件分离；
- 冷却 Tick；
- 暂停后恢复、重新开始或取消；
- 目标失效后重新选择；
- 动作完成后是否允许再次触发。

例如保持攻击距离时：

```text
敌人距离 < 攻击距离 × 70%：开始后退
敌人距离 ≥ 攻击距离 × 85%：停止后退
```

两个不同阈值用于防止英雄在边界附近反复切换动作。

### 9.7 局部接受与玩家确认

一份策略可以包含多条意图。某条意图不支持时：

- 该意图被标记为拒绝；
- 与它存在必要依赖的后续意图一并拒绝；
- 其他独立意图仍然可以编译；
- 客户端用红色说明展示未执行原因；
- 玩家确认系统理解结果后才能开始模拟。

### 9.8 当前已知自然语言限制

当前本地快速解析器主要擅长带明确编号的中文语句。集合代词目前仍存在覆盖不足，例如：

```text
其他人
其余英雄
除5号以外的人
```

这类表达可能不能被本地解析器正确展开。现阶段更稳定的输入方式是明确写出：

```text
1号、2号、3号、4号优先攻击僧侣。
```

这是当前自然语言理解层的限制，不是战斗引擎缺少攻击僧侣的能力。

### 9.9 旧策略兼容

工程中仍保留 Strategy 2.0 的校验器和运行时，用于兼容已有旧策略数据。当前客户端的新建、编译、确认和服务器权威模拟主流程使用 Strategy 3.0；新增功能应以 Strategy 3.0 为准，不继续扩展 Strategy 2.0。

## 10. 服务器权威模拟

### 10.1 不可变战斗快照

开始策略编译前，服务器根据当前阵容生成战斗快照。快照包含：

- 游戏版本；
- 引擎版本；
- 地图版本和当前支持区域；
- 双方英雄编号、类型和固定数值；
- 每个英雄当前能力；
- 快照哈希。

客户端不能自行声明草丛、技能或地图能力。

### 10.2 编译绑定

服务器保存并绑定：

- 玩家 ID；
- `compileId`；
- `snapshotHash`；
- `planHash`；
- 元数据版本；
- 编译器版本；
- 过期时间。

玩家确认时必须提交完全一致的快照和策略哈希，防止预览内容与实际执行内容不一致。

### 10.3 随机种子

练习模式允许使用指定种子，也可以由服务器第一次请求时生成随机种子。移动端使用同一战斗请求 ID 重试时，继续使用第一次绑定的种子，不会重新抽取战局。

正式模式相关接口已经预留服务器生成种子规则，客户端不能指定正式比赛种子；当前客户端实际使用练习模式。

### 10.4 幂等与安全重试

每次确认模拟使用唯一 `battleRequestId`。相同玩家和相同请求 ID：

- 只能绑定同一个编译结果和种子；
- 并发请求只允许一个模拟任务执行；
- 已完成请求直接返回同一结果；
- 基础设施临时失败可以使用同一请求安全重试；
- 客户端当前会在网络失败时自动重试一次。

### 10.5 模拟上限

| 项目 | 当前上限 |
|---|---:|
| 固定模拟频率 | 60 Tick/秒 |
| 最大战斗 Tick | 10800 |
| 最大战斗时间 | 180秒 |
| 单次模拟进程墙钟超时 | 15秒 |
| 回放采样间隔 | 0.1战斗秒 |
| 服务器并行回放模拟数 | 2 |
| 热回放缓存数量 | 4 |

180 秒或 10800 Tick 内未分出胜负时，服务器以 `TIME_LIMIT_DRAW` 结束并判定平局。

## 11. 胜负规则

当前基础胜负目标是消灭敌方全部英雄。

系统会先处理肉复活，再检查存活英雄数量。结果规则为：

- 蓝方仍有存活英雄、红方无存活英雄：胜利；
- 红方仍有存活英雄、蓝方无存活英雄：失败；
- 双方同时无存活英雄：平局；
- 达到服务器时间/Tick上限且双方仍未被消灭：平局。

当前没有占点、积分、Boss 或其他胜利条件。

## 20. 当前版本的核心玩法总结

客户端 `0.7.7` 的实际玩法可以概括为：

```text
玩家从五种英雄中自由重复选择2—5人
  → 通过编号为英雄安排自然语言策略
  → 系统把策略编译成确定性规则并解释给玩家
  → 双方在双桥地图自动移动、攻击、治疗和采集
  → 弓箭手的箭可被敌方前排真实拦截
  → 工人采集四类资源，其中肉可以复活死亡英雄
  → 服务器模拟至一方全灭或180秒超时
  → 客户端播放回放并保存历史战绩
  → 玩家修改阵容或策略继续挑战
```

当前游戏最具辨识度的三个系统是：

1. 自然语言团队策略；
2. 英雄战斗、工人采集和肉复活同时存在的取舍；
3. 双桥路径与弓箭实体拦截带来的站位价值。
